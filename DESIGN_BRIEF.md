# YallaBalagan — Design Brief для редизайна публичного сайта

## О проекте

**YallaBalagan** — творческое объединение в Израиле. Стендап, шоу, подкасты, музыкальные вечеринки.  
Аудитория — русскоязычные жители Израиля.  
Сайт: продажа билетов + афиша + мерч исполнителей.

**Референс стиля:** уже утверждённый прототип главной страницы (файл `2026-05-21 11.10.05.jpg` в корне).  
Стиль — смелая типографика, кричащие акценты (жёлтый / ярко-розовый / голубой), энергичный, андеграундный.

**Языки:** русский (основной), иврит, английский. UI на русском, переключатель языка в хедере.

**Технически:** статический сайт (HTML генерируется из базы данных). Без SPA — каждая страница отдельный HTML файл.

---

## Глобальные компоненты (используются на всех страницах)

### Header
- Логотип / название ЯЛЛА БАЛАГАН
- Навигация: Программа · Исполнители · Подкаст · О нас
- Переключатель языка: RU / HE / EN
- Кнопка «Купить билет» (CTA)

### Footer
- Короткое описание
- Адрес и контакты
- Ссылки: Privacy · Terms · Accessibility
- Соцсети

## Экраны

---

### 1. Главная страница (`/index.html`)

**Цель:** первое впечатление, быстрый доступ к ближайшим событиям, погружение в бренд.

**Блоки сверху вниз:**

1. **Hero** — большой заголовок «ЯЛЛА, БАЛАГАН» (как в прототипе), подзаголовок, кнопки «Купить билет» и «Подписаться»

2. **Фильтр по тегам** — горизонтальная строка кнопок-тегов: СТЕНДАП · ПОДКАСТ · ВЕЧЕРИНКИ · ОПЕН МИК · (и другие). Клик фильтрует события на странице без перезагрузки.

3. **Баннер кампании** (если активна) — яркая полоса: «КАМПАНИЯ — собираем деньги на новый сезон шоу» + кнопка «Поддержать →». Может отсутствовать.

4. **Ближайшие события** — заголовок «ПРОГРАММА» + месяц/год + счётчик «N событий». Список карточек событий (не сетка, а именно список — как в прототипе). Показывать ближайшие 5–7.

5. **Ссылка «Все события →»** — переход на `/events.html`

6. **Блок подкаста** — «ЧЕ ТАМ У ЕВРЕЕВ». Название подкаста, короткое описание, название последнего выпуска + дата (генерируется из YouTube API при сборке сайта), кнопки «Смотреть на YouTube» и «Слушать в Spotify».

7. **Соцсети** — четыре плитки: Instagram · Telegram · YouTube · Facebook

**Карточка события в списке:**
- Левая колонка: число + месяц крупно (07 / ДЕК)
- Центр: теги события (СТЕНДАП, ОТКРЫТЫЙ), название, короткое описание, адрес/площадка
- Правая колонка: цена «БИЛЕТ ОТ 100₪» + кнопка «Оторвать»
- Для внешних событий (без билетов): кнопка «Подробнее →» вместо цены

---

### 2. Все события (`/events.html`)

**Цель:** полная афиша, поиск и фильтрация.

**Блоки:**
1. Заголовок «ВСЕ СОБЫТИЯ»
2. Фильтр по тегам (те же кнопки что на главной)
3. Полный список событий в том же формате карточек что на главной
4. Пустое состояние: «По этому тегу пока нет событий»

**Отличие от главной:** все события, не только ближайшие 5–7.

---

### 3. Страница события (`/events/{slug}.html`)

**Цель:** полная информация о событии, покупка билета.

**Блоки:**
1. **Hero image** — широкое изображение события
2. **Теги** события (СТЕНДАП · ОПЕН МИК)
3. **Заголовок** события
4. **Мета-информация:** дата и время · площадка (ссылка) · адрес
5. **Описание** — полный текст
6. **Секция исполнителей** (если есть) — горизонтальная полоса: фото-кружок + имя + роль. Клик → страница исполнителя.
7. **Блок покупки билетов:**
   - Для **внутреннего события:** типы билетов с ценами + кнопка «Купить» (или выбор мест если зал с рассадкой)
   - Для **внешнего события:** кнопка «Перейти на сайт →» (открывает external_url)
   - Если билеты закончились: «Распродано»
   - Если событие прошло: блок скрыт
8. **Карта / адрес** площадки

**Вариант с рассадкой:** вместо кнопки «Купить» — интерактивная схема зала с выбором мест. После выбора мест — переход на checkout.

---

### 4. Страница исполнителя (`/performers/{slug}.html`)

**Цель:** представить исполнителя, показать его мерч.

**Блоки:**
1. **Hero** — большое фото исполнителя + имя + роль (DJ / Singer / Band / etc.)
2. **Биография** — текст, может быть длинным
3. **Галерея фото** (если есть несколько фото)
4. **YouTube embed** (если есть) — один видеоплеер
5. **Соцсети** исполнителя — иконки (Instagram / Telegram / YouTube / Facebook)
6. **Ближайшие события** с этим исполнителем — мини-список (2–3 события)
7. **Мерч / товары** — сетка карточек товаров (фото, название, цена, кнопка «Купить»)

---

### 5. Checkout / Оформление заказа (`/checkout.html`)

**Цель:** сбор данных покупателя и оплата.

**Существует в двух вариантах:**
- **Обычный** (стоячий зал): покупатель выбрал тип и количество билетов на странице события
- **С рассадкой**: покупатель выбрал конкретные места на схеме зала

**Блоки:**
1. **Итог заказа** (правая колонка / вверху на мобильном):
   - Название события, дата, площадка
   - Список билетов: тип · количество · цена
   - Промокод (поле + применить)
   - Итоговая сумма

2. **Форма покупателя:**
   - Имя (обязательно)
   - Email (обязательно)
   - Телефон (обязательно)
   - Telegram (опционально)

3. **Блок оплаты** (AllPay Hosted Fields — встраиваемые поля карты)

4. **Кнопка «Оплатить N₪»**

5. **Состояния:**
   - Загрузка (spinner)
   - Ошибка валидации (inline под полями)
   - Ошибка оплаты (toast / banner)

---

### 6. Обработка платежа (`/processing.html`)

**Цель:** держать пользователя в курсе пока идёт проверка оплаты.

**Три состояния — три разных экрана:**

1. **Обработка** — анимация загрузки, «Обрабатываем платёж...», просьба не закрывать страницу

2. **Успех** — яркий экран подтверждения:
   - «Готово! Билет у тебя 🎉»
   - Название события, дата
   - QR-код(ы) билета (один на каждый билет)
   - Уведомление «Отправили на email»
   - Кнопка «Вернуться на главную»

3. **Ошибка** — «Что-то пошло не так»:
   - Описание ошибки
   - Кнопка «Попробовать снова»
   - Контакт поддержки

---

### 7. Подтверждение заказа (`/orders/{order_id}.html`)

**Цель:** страница-квитанция, доступна по прямой ссылке (из письма).

**Блоки:**
1. Заголовок «Твой билет»
2. Название события, дата, площадка, адрес
3. Данные покупателя (имя, email)
4. Список билетов
5. **QR-код(ы)** — крупно, один на каждый билет, под ним: тип билета + место (если рассадка)
6. Итоговая сумма

---

### 8. Площадка (`/locations/{slug}.html`)

**Цель:** информация о площадке, ближайшие события здесь.

**Блоки:**
1. Название площадки
2. Адрес + ссылка на Google Maps
3. Описание (если есть)
4. **Ближайшие события на этой площадке** — список карточек (формат как на главной)

---

## Мобильная версия — ключевые требования

- Все страницы полностью адаптивны (основная аудитория — мобильные)
- Hamburger-меню на мобильном
- Checkout: форма и итог — вертикально, форма снизу
- Схема зала (рассадка): поддержка touch/pinch-zoom
- QR-коды на странице успеха — крупно, без необходимости зумить

## Данные которые приходят из системы (для дизайнера: что всегда есть, что опционально)

| Поле | Обязательно | Примечание |
|------|-------------|------------|
| Название события | ✓ | |
| Дата и время | ✓ | |
| Описание | ✓ | |
| Изображение события | — | Может отсутствовать, нужен красивый fallback |
| Теги | — | Список строк: «Стендап», «Вечеринка», etc. |
| Площадка | — | |
| Цена от | — | Нет у внешних событий |
| Исполнители | — | Список, может быть пустым |
| Фото исполнителя | — | Нужен fallback-аватар |
| Tagline исполнителя | — | Одна строка: «Тель-Авивский комик, автор шоу Изотоп Комедия» |
| YouTube embed исполнителя | — | |
| Товары исполнителя | — | |

## Что НЕ входит в этот редизайн

- Админ-панель (отдельная задача, меньший приоритет)
- Страница доната (отдельный сервис)
